# makruk-tb: ตัวสร้างตารางท้ายเกมหมากรุกไทย (Rust)

โปรแกรมสร้างตารางท้ายเกม (endgame table) บนเครื่องของคุณ เร็วกว่าตัวสร้าง JavaScript ใน `scripts/` หลายสิบเท่า และใช้ได้กับท้ายเกมที่ **ทั้งสองฝ่ายมีหมาก** เช่น ขุน+เรือ+เบี้ยหงาย 2 vs ขุน+เรือ

- ตรวจทุกตำแหน่งเทียบกับกติกาเดียวกับเว็บ (`makruk-rules.js`): เบี้ยหงายกับเม็ดเดินเหมือนกัน โคนขาวเดินหน้าไปทางแถว 8 อับ = เสมอ
- คิดย้อน (retrograde) ทีละชั้นความลึก ใช้ CPU ทุกเธรด
- ใช้หน่วยความจำ 2 ไบต์ต่อตำแหน่ง (ฝ่ายละ 1 ไบต์ที่ถึงตาเดิน)
- ตารางที่สร้างเสร็จเก็บไว้ใน `tablebase-local/` (git ไม่สนใจ) ถ้าหยุดกลางคัน สั่งใหม่แล้วชุดที่เสร็จแล้วไม่ต้องสร้างซ้ำ

## ติดตั้ง

1. ติดตั้ง Rust ด้วย [rustup](https://rustup.rs) บน Windows ใช้ชุด GNU ได้โดยไม่ต้องลง Visual Studio:

   ```bash
   rustup default stable-x86_64-pc-windows-gnu
   ```

2. คอมไพล์ (ในโฟลเดอร์ `tools/makruk-tb`):

   ```bash
   cargo build --release
   ```

   ได้โปรแกรมที่ `target/release/makruk-tb` (`makruk-tb.exe` บน Windows)

## คำสั่ง

### สร้างตาราง

```bash
target/release/makruk-tb build KRMMvKR
```

ชื่อชุดหมาก: `K` ตามด้วยหมากฝ่ายขาว, `v`, แล้ว `K` ตามด้วยหมากฝ่ายแดง

| ตัวอักษร | หมาก |
| --- | --- |
| R | เรือ |
| N | ม้า |
| S | โคน |
| M | เม็ด หรือ เบี้ยหงาย |

เช่น `KRMMvKR` = ขุน+เรือ+เบี้ยหงาย 2 vs ขุน+เรือ ตารางย่อยทุกชุดที่การกินหมากพาไปถึง จะถูกสร้างก่อนโดยอัตโนมัติ

ตัวเลือก: `--out โฟลเดอร์` (ค่าปกติ `tablebase-local/` ของ repo), `--threads จำนวน` (ค่าปกติ ใช้ทุกเธรด),
`--disk` สร้างในไฟล์บนดิสก์ (memory-mapped) แทน RAM สำหรับตารางที่ใหญ่กว่าหน่วยความจำ (ช้ากว่าราว 2–3 เท่า ระหว่างสร้างไฟล์ชื่อ `.bin.part`
ได้ผลเหมือนสร้างใน RAM ทุกไบต์) เช่น

```bash
target/release/makruk-tb build KRRvKRS --disk --out D:/makruk-tb
```

ไฟล์ที่ได้ต่อชุด: `<ชื่อ>.w.bin` (ขาวเดิน), `<ชื่อ>.b.bin` (แดงเดิน) และ `<ชื่อ>.json` (วิธีเรียงตำแหน่งและสถิติ ให้โปรแกรมภาษาอื่นอ่านได้) ไฟล์ `.bin` เก็บไบต์ละตำแหน่ง:
`0` เสมอ, `1–124` ฝ่ายที่เดินรุกจนได้ในจำนวนตานั้น, `128+n` ฝ่ายที่เดินโดนรุกจนหลังอีกฝ่ายเดิน n ตา (`128` = โดนรุกจนแล้ว)
`125` / `253` คือชนะ / แพ้ที่ต้องใช้ **125 ตาขึ้นไป** (ยังรู้แพ้ชนะถูกต้อง แต่ไม่นับจำนวนตา ตามกติกาการนับศักดิ์ การไล่ยาวขนาดนั้นยังไงก็จบเสมอก่อน) มีในบางชุด เช่น ขุน+โคน+เม็ด vs ขุน+เม็ด
ตารางยังไม่รวมการนับศักดิ์ ตอนใช้งานต้องเทียบจำนวนตากับการนับเอง

### ส่งออกให้เว็บ (GitHub Pages)

```bash
target/release/makruk-tb export KRvKR KRvKM KMMvKR KRMvKR KRMMvK
```

แปลงตารางจาก `tablebase-local/` (สร้างให้ก่อนถ้ายังไม่มี) เป็นไฟล์สำหรับเว็บใน `tablebase/rs/` ซึ่งขึ้น git และใช้บน GitHub Pages ได้:

- เก็บเฉพาะตาขาวเดิน เว็บคิดตาแดงเดินเพิ่มอีก 1 ตาเอง
- ตารางไม่เกิน 8 MB เป็นไฟล์เดียว (`all.bin`) ตารางใหญ่แบ่งตามช่องขุนทั้งสองฝ่าย ไฟล์ละคู่ช่อง เว็บโหลดเฉพาะส่วนที่ตำแหน่งนั้นต้องใช้
- ส่วนที่เสมอทั้งหมดไม่มีไฟล์ (บอกไว้ใน `info.json`)
- `tablebase/rs/index.json` บอกว่ามีตารางชุดไหนบ้าง

ใช้เฉพาะกับตารางที่ไม่ใหญ่เกินไป (หมากรวมไม่เกิน 5 ตัว) ตาราง 6 ตัวให้ใช้ผ่านโปรแกรมตอบบนเครื่อง

ตัวเลือกเพิ่ม:

- `--sample N` ตรวจ N ตำแหน่งสุ่มก่อนส่งออก
- `--to โฟลเดอร์` ส่งออกไปที่อื่นแทน `tablebase/rs/` เช่น `tablebase-local/packed` สำหรับโปรแกรมตอบ (แบบบีบอัด ประหยัดดิสก์ราว 10 เท่า)
- `--drop-raw` ลบไฟล์ดิบของชุดนั้นหลังส่งออก (อย่าใช้กับชุดที่ชุดใหญ่กว่ากินลงมาถึงแล้วยังต้องสร้างต่อ)

ชุดที่ใช้บนเว็บตอนนี้ (ขุน + หมาก 3 ตัว vs ขุนเดี่ยว ครบ 20 ชุด) และชุดบนเครื่อง (ขุน + หมาก 2 ตัว vs ขุน + หมาก 1 ตัว) สร้างด้วย:

```bash
target/release/makruk-tb export KMMMvK KRRRvK … --sample 200000 --drop-raw
target/release/makruk-tb export KRRvKR KRRvKN … --to ../../tablebase-local/packed --sample 200000 --drop-raw
```

โปรแกรมตอบอ่านทั้งแบบดิบ (`tablebase-local/*.bin`) และแบบบีบอัด (`tablebase-local/packed/`) แบบบีบอัดเก็บเฉพาะตาขาวเดิน ตาแดงเดินคิดเพิ่ม 1 ตาเอง

### โปรแกรมตอบบนเครื่อง (ตาราง 6 ตัว)

ตารางที่ใหญ่เกินกว่าจะขึ้นเว็บ (เช่น `KRMMvKR` 10.6 GB) ใช้ได้เมื่อเปิดเว็บแบบ local บนเครื่องนี้

**แบบคลิกเดียว (Windows):** ดับเบิลคลิก `tools/makruk-tb/serve-local.bat` จะเปิดโปรแกรมตอบ (ข้อ 1) และเว็บ (ข้อ 2)
ในหน้าต่างของตัวเอง แล้วเปิดเบราว์เซอร์ที่ `http://localhost:8000/ai/` ให้ (ถ้าเปิดอยู่แล้วจะไม่เปิดซ้ำ ถ้ายังไม่มี
`makruk-tb.exe` จะ build ให้ก่อน) เลิกใช้ก็ปิดสองหน้าต่างนั้น หรือทำเองทีละขั้น:

1. เปิดโปรแกรมตอบค้างไว้ (ในโฟลเดอร์ `tools/makruk-tb`):

   ```bash
   target/release/makruk-tb serve
   ```

   เปิดที่ `http://127.0.0.1:8765` (เปลี่ยนด้วย `--port`) และรับเฉพาะจากเครื่องนี้ จะแสดงรายชื่อตารางที่อ่านได้จาก `tablebase-local/` ไฟล์ตารางถูก map จากดิสก์ จึงไม่ต้องโหลดทั้งหมดเข้า RAM
2. เปิดเว็บแบบ local อีกหน้าต่าง (ที่โฟลเดอร์ของ repo) แล้วเข้า `http://localhost:8000`:

   ```bash
   python -m http.server 8000
   ```

3. เมื่อกระดานเหลือหมากตรงกับตารางที่มีแค่บนเครื่อง AI ระดับกลาง/เซียน คำใบ้ และหน้าถอดหมากจะถามโปรแกรมตอบเอง หน้าถอดหมากจะแสดง **(ตาราง local)** ถ้าไม่ได้เปิดโปรแกรมตอบ หรือเปิดเว็บจาก github.io ทุกอย่างทำงานเหมือนเดิม

โปรแกรมตอบมี `/status` (รายชื่อตาราง) และ `/probe?fen=<FEN>` (ผลของตำแหน่งและของทุกตาเดิน) ตอบเฉพาะหน้าเว็บที่เปิดจาก `localhost` / `127.0.0.1`

### ตรวจความถูกต้อง

```bash
target/release/makruk-tb check
```

- สร้างตารางที่เว็บมีอยู่แล้วใหม่ (`tablebase/krk.bin` และชุดหมาก 1–2 ตัวทั้ง 12 ชุด) แล้วเทียบทุกตำแหน่ง
- ชุดที่ทั้งสองฝ่ายมีหมาก (ไม่มีตารางเดิมให้เทียบ) ตรวจว่าทุกตำแหน่งตรงกับผลของตาเดินถัดไปทุกตา
- `--big tablebase/<ชื่อ>` เทียบกับตารางหมาก 3 ตัวที่สร้างด้วย `scripts/build-big-tables.cjs` เพิ่มได้

ใช้เวลาราว 2 นาที

ตรวจขั้นที่คิดการไล่เกิน 124 ตา (ตั้งเพดานไว้แค่ 8 ตา แล้วเทียบกับการสร้างปกติทุกตำแหน่ง):

```bash
target/release/makruk-tb selftest
```

ตรวจตาราง local แบบบีบอัดผ่านโปรแกรมตอบที่เปิดอยู่:

```bash
node scripts/check-local-server.cjs
```

ตารางที่ใหญ่เกินจะตรวจทุกตำแหน่ง ใช้แบบสุ่ม (ค่าปกติ 1,000,000 ตำแหน่ง):

```bash
target/release/makruk-tb check KRMMvKR --sample 1000000
```

### ตรวจด้วยกติกาของเว็บ (คนละโค้ดกับตัวสร้าง)

```bash
node scripts/check-local-tables.cjs
```

อ่านทุกตารางใน `tablebase-local/` ด้วย JavaScript สุ่มตำแหน่งชุดละ 3,000 ตำแหน่ง (ตั้ง `MAKRUK_SAMPLES` เพื่อเพิ่ม) ตรวจกับ `makruk-rules.js` ว่าค่าตรงกับผลของตาเดินถัดไป และเดินไล่ตามตารางจนรุกจนได้ในจำนวนตาที่บอก

## เวลาและขนาด (Ryzen 5 7500F, 12 เธรด, RAM 32 GB)

| ชุด | ตำแหน่ง (ต่อฝ่ายที่เดิน) | เวลา | ไล่จนนานสุด |
| --- | --- | --- | --- |
| ชุดหมาก 1–2 ตัว (vs ขุนเดี่ยว) | ≤ 8.4 ล้าน | ≤ 3.5 วินาที ต่อชุด | 57 ตา |
| KMMMvK (เบี้ยหงาย 3) | 26.7 ล้าน | ~9 วินาที | 40 ตา |
| KRMvKR | 168 ล้าน | 30 วินาที | 34 ตา |
| KMMvKR | 83 ล้าน | 24 วินาที | 59 ตา |
| KRMMvK | 83 ล้าน | 18 วินาที | 16 ตา |
| KRMMvKR (เป้าหมาย) | 5,285 ล้าน | 19.3 นาที (วัดจริง, RAM 10.1 GB) | 111 ตา |
| KRMvKNM (เรือ+เบี้ยหงาย vs ม้า+เบี้ยหงาย) | 10,737 ล้าน | 58.4 นาที (วัดจริง, RAM 21.5 GB) | 125 ตาขึ้นไป |
| KRRvKRS (เรือ 2 vs เรือ+โคน) | 16,911 ล้าน | 2.7 ชั่วโมง (วัดจริง, `--disk`, ไฟล์ดิบ 33.8 GB) | 63 ตา |

ไฟล์ดิบ = 2 ไบต์ × จำนวนตำแหน่ง (KRMMvKR ≈ 10.6 GB, KRMvKNM ≈ 21.5 GB) RAM ที่ใช้ตอนสร้างเท่ากับขนาดนั้น และชุดที่มีการไล่จนเกิน
124 ตาใช้เพิ่มอีกราว 4 บิตต่อตำแหน่งในรอบท้าย (KRMvKNM ราว 5 GB: ให้ Windows ขยาย pagefile เองได้ หรือปิดโปรแกรมอื่นก่อน)
แบบบีบอัดใน `tablebase-local/packed/` เล็กลงมาก (KRMvKNM 3.4 GB)
